# Data round 1 — enough events for the Stage A gates (remote `rtx3060`)

Goal: the gate numbers of spec §10.1 stop being noise. Pilot val had 39 events (8 unrevealed, 2 failures;
3 revealed, 0 failures; 11 occlusion events). Target after this round: ≥ 100 unrevealed val events with ≥ 20
failures, and a revealed control with failures. Then retrain Stage A (POL, Markov) and rerun the gates.
Not in scope: the -5/-6 tasks, the eval split, Stage B.

**4 workers**. RAM (64 GB free) and CPU (64 cores) are not limiting. Do not touch the Isaac Sim process.

Expected val (last 10 % of seeds per task, i.e. new seeds only): ~30 episodes/task → ~100 SB+BS unrevealed
outcome events with ~20 failures; ~100 GI revealed events. AUROC standard error ≈ 0.04 instead of ≈ 0.2.

Run (remote, after `git pull`):
```bash
cd /home/ubuntu/workspace/pending-outcome-ledger
setsid nohup bash scripts/pol/run_round.sh > /dev/null 2>&1 < /dev/null &
tail -f logs/round1/progress.log          # one line per chunk / phase
touch logs/round1/STOP                    # stop cleanly after the current chunk; rerun the command to resume
```
Settings by env: `CHUNKS`, `CHUNK`, `WORKERS`, `TASKS`, `SEED_BASE` (default 10000, apart from pilot seeds),
`STEPS_POL`. Resuming skips finished chunks (their `summary-train-<seed>.json`) and episodes with features;
a chunk killed midway is redone from its first seed.

## Blocker to fix in parallel (does not block collection)

GatherInject (the **revealed** control for N1) has 21 labelled outcome events, all `in`, although injection is
slip 0.15 + place_drift 0.1 per drop (P(0 failures) ≈ 0.2 %) and episode 3 ended with cube 1 `ELSEWHERE`
after its release at t=123. Probably the FSM sees that release as `R0` (gripper closed empty after a slip), so
`labels.event_outcomes` returns None. Labels are computed from the per-step logs (`cube_location`,
`release_cube`), so this can be fixed afterwards without recollecting. Until then N1's revealed condition and
the G1 numbers on GatherInject are not trustworthy.
